# 04 · 世界生成设计（世界模型 · 一级世界 · 权重提取 · 二级世界）

> 本文是第 3、4、5 段的设计。第 6 段（现实情境与坍缩）在 `05-现实情境与坍缩设计.md`，两篇共用 §5 的手算例子。
> 每一处建模假设都标注三类来源之一：**【典籍】** 来自命理典籍的规则；**【数学】** 来自博弈论、概率论或量子力学的标准数学；**【自定】** 项目自定义的假设（没有外部依据，未经校准，可调，必须版本化）。

## 0. 结论先行

1. **世界 = 一组人物与环境的离散状态，按年推进。** 人物（本人与他人）的状态是少量离散变量（学业阶段、职业状态、婚恋状态、居住地、子女数、与本人是否同城等），不是 0–100 分数。环境分「过去的固定背景」（有出处的历史事实）和「未来的环境参与者」（其策略被穷举）。
2. **一级世界由「人 × 引擎」生成，是有限的。** 一个引擎对一个人的一级世界，是该引擎的倾向序列加上若干分岔点；分岔点只来自引擎的 `key_node` 信号，每个分岔点分成「应验 / 未应验」两支。一级世界惰性定义、不物化。
3. **重大选择用可判定的公式提取。** 引擎的关键节点经一张「领域 × 当事人 → 选择类型」映射表变成候选选择；权重 = 重要性 × 可靠性，跨引擎、跨人物用带相关折扣的 noisy-OR 合并；按权重取前 K 个进入二级世界（K 是写入输出的物化边界）。权重是项目自定的主张，不是概率。
4. **二级世界是一个带「环境」参与者的多阶段博弈。** 每个重大选择是一个阶段博弈：本人、相关他人同时选策略，环境按先验选状态；前面阶段的结果写入状态，改变后面阶段的参与者、可用策略和收益。参与者的收益由**各自的**引擎信号给出。策略分布用 logit 量化响应均衡（QRE）求出，它是标准博弈论概念，当理性参数趋于无穷时收敛到纳什均衡。
5. **「无穷」的形式化**：世界的地址是「每个选择节点的结果 + 时间细化层级」组成的序列。任一有限精度的地址都可以纯函数地生成对应节点；精度可以无限细分，所以世界空间是可数无穷、良定义的。物化多少由三个显式边界决定：选择数上限 K、时间精度 r、推演边界年份 H。这三个值写入输出。
6. **你的设想里有一处我改了**：你设想每个选择上「穷举全部策略组合，每个组合产生一个分支」。我把**分支定义在「结果」上而不是「策略组合」上**。原因是：多个策略组合会导致同一个现实结果（比如「我拒绝」和「对方拒绝」都导致「没结婚」），而现实只能观测到结果、观测不到策略。如果按策略组合分支，坍缩时会出现大量现实中无法区分的世界。策略组合仍然被完整穷举，它们的概率汇总到所导致的结果上。

## 1. 世界模型

### 1.1 世界里有什么

| 实体 | 说明 | 来源 |
|---|---|---|
| `Person` 人物 | 本人，以及用户录入的他人（父母、兄弟姐妹、配偶伴侣、子女、师长、上司、合作者、对手等）。分两种：**完整人物**（有出生信息，对他运行全部引擎，有自己的一级世界）和**推导人物**（无出生信息，由本人命盘的 `relationSlots` 推出，没有独立世界） | 用户输入；引擎 `relationSlots`【典籍】 |
| `Relation` 关系 | 两个人物之间的有向关系：类型（父、母、配偶…）、起止年份、是否同住、是否同城 | 用户输入；世界演化 |
| `Household` 家庭 | 某时刻同住的人物集合、家庭经济档位（相对同地同期的分档）、家庭变故记录 | 用户输入（现实情境） |
| `Place` 地域 | 国家或地区代码（ISO 3166）、城乡、可选城市 | 用户输入 |
| `EraRecord` 时代记录 | 「国家或地区 × 年」的历史事实条目，每条带出处 | `era-data` 数据集（§1.4） |
| `EnvironmentPlayer` 环境参与者 | 未来时段中，环境作为博弈参与者，其策略（如「扩张 / 平稳 / 收缩」）被穷举 | 【自定】 |

**明确不建模的东西**：人物的心理细节、具体对话与情节、具体雇主名称、具体疾病。模型做不到的细节一律不生成。

### 1.2 状态的结构化定义

世界状态 `WorldState` 在每个时间步（年）记录每个人物的一组离散变量。第一版的变量表如下，所有取值都是枚举或小整数，不存在 0–100 的连续分数。

| 领域 | 变量 | 取值 | 说明 |
|---|---|---|---|
| 学业 `study` | `educationStage` | `none / primary / secondary / tertiary / postgraduate` | 已完成的最高阶段 |
| | `inEducation` | 布尔 | |
| 事业 `career` | `workStatus` | `not_working / employed / self_employed / between_jobs / retired` | |
| | `careerLevel` | 0–3 | 只有用户事实或选择结果能改变，引擎不直接设定 |
| 财富 `wealth` | `wealthBand` | 0–4 | 相对「同地同期」的分档；有时代数据时按当地分位数定义，没有时只在用户事实中出现 |
| 情感 `relationship` | `partnership` | `single / partnered / married / separated` | 不含「丧偶」：见 §1.5 |
| 家庭 `family` | `childrenCount` | 整数 | |
| | `caregiving` | `none / for_parent / for_child / both` | |
| 迁移 `migration` | `residence` | `Place` | |
| | `coLocatedWith` | 人物 ID 集合 | 与哪些人同城，由居住地推出 |
| 健康 `health` | `healthAttention` | `none / attention` | 只表示「该时段需关注」，不做诊断，不进入任何死亡或寿命推断 |
| 关系 | `relation[p→q].closeness` | `distant / normal / close` | 只来自用户事实，第一版不由引擎驱动 |

「重大转折 `turning`」不是状态变量，是一级世界里的时间结构标记（例如大运交接），见 §2.3。

### 1.3 状态如何演化，如何影响选择

状态只在两种情况下改变，没有第三种：

1. **重大选择的结果**（§4）：每种选择类型在「选择目录」`ChoiceCatalog` 中声明它读写哪些状态变量。例如 `partnership`（结成或解除伴侣关系）在 `single` 时实例化为「结成」，在 `married` 时实例化为「解除」。
2. **用户事实**（现实情境，见 05 文档）：事实直接设定某年的状态。

旧代码里那种「健康每年自然下降 0.5」之类的自然漂移，新设计一律不做，因为它没有来源。

状态对选择的三种作用（全部写进 `ChoiceCatalog`，全部是【自定】）：

| 作用 | 例子 |
|---|---|
| **前置条件**：决定选择是否存在、实例化成什么 | `partnership` 在 `married` 时变成「是否解除」 |
| **参与者**：决定谁参与这个选择 | `residence`（迁居）中，已婚则配偶是参与者；本人与父亲同城时，父亲是参与者 |
| **收益修正**：决定策略的代价 | 与父亲同城时迁走，本人收益减去「父亲反对的概率 × 0.5」 |

### 1.4 环境如何进入世界

**过去：固定背景，不分岔。** 数据集 `era-data` 按「ISO 3166 国家或地区代码 × 年」组织，每条记录：

```ts
interface EraRecord {
  recordId: string;          // 'CN.2020.who-pandemic-declaration'
  region: string;            // ISO 3166-1 alpha-2，或 alpha-2 + 子区划
  yearFrom: number; yearTo: number;
  kind: 'indicator' | 'event' | 'institution';
  key: string;               // 指标代码，如 World Bank WDI 'SE.TER.ENRR'
  value: string | number | null;
  source: { publisher: string; title: string; url: string; retrieved: string; license: string };
  datasetVersion: string;    // 'era-data/2026.1'
}
```

- **数据来源**分三层（详见 10 文档 D2）：① 国际机构的机器可读指标（World Bank WDI 等，覆盖约 1960 年以后、国家级）；② 有明确发布机构和日期的重大事件（例如世卫组织于 2020-03-11 将 COVID-19 定性为大流行）；③ 人工整理的制度类条目（如某国义务教育年限），每条需两人复核。**没有可靠来源的国家或年代如实留空，不生成。**
- **准确性**：只收录带 URL 和取用日期的条目；数值保留原始单位；数据集整体版本化，算法输出记录所用的 `datasetVersion`。
- **第一版的作用范围（诚实说明）**：时代记录作为世界背景展示，并作为人物状态的上下文；但「某个指标如何定量地改变某个选择的概率」没有规则依据。第一版**不把时代数值映射成概率**，只在两处使用：选择是否可得（例如某国某年代是否存在高等教育选项），以及作为现实情境中「成长环境」条目的标准化取值。把时代数据变成选择的基准发生率（例如当地当年的初婚率）是第二版的方向，见 §4.6。

**未来：环境是博弈参与者。** 未来时段的环境走向未知，第一版每个相关选择的环境参与者有三个策略「扩张 / 平稳 / 收缩」，先验均匀分布（各 1/3）【自定：最大熵假设，不做任何经济预测】。环境的策略影响**结果**，而不影响人物当时的决策（人物在决策时不知道环境走向）。

### 1.5 真实性的含义与限度

世界状态里的每一项都必须属于以下四类之一，并在数据上带标签 `provenance`：

| 标签 | 含义 |
|---|---|
| `engine_rule` | 来自某引擎某条规则（带 `ruleId`） |
| `user_fact` | 来自用户提供的事实（带现实情境条目 ID） |
| `historical_record` | 来自有出处的历史记录（带 `recordId`） |
| `enumerated` | 博弈穷举出的可能性（带世界地址） |

不属于以上四类的内容不能出现在世界里。具体情节（「你在某公司遇到某人」）不生成。

**关于死亡**：类型层面不存在任何人的死亡或寿命事件。用户可以在现实情境中提供「某位亲人已于某年离世」这样的过去事实，它只作为 `user_fact` 改变关系的有效期，系统从不推演任何人的死亡。因此 `partnership` 没有「丧偶」这个由推演产生的取值。

## 2. 一级世界

### 2.1 定义

对人物 `p` 和引擎 `e`，一级世界 `W(p,e)` 由三部分组成：

- **时间结构**：引擎交付的 `timeline`（大运、流年、大限、Dasha 等），保留引擎自有的时间单位，每个单位同时带绝对日期边界（由 `astro-time` 计算）。
- **倾向**：所有 `kind: 'tendency'` 的信号，按（时段，领域，当事人）组织。
- **分岔点**：所有 `kind: 'key_node'` 的信号，按 `(ruleId, periodId, subjectRole)` 分组，**一组为一个分岔点**。同一规则在同一时段对同一当事人触发、涉及多个领域时，算一个分岔点（这回答了八字设计文档 §7 留下的未决问题）。

每个分岔点有两支：「应验」（该领域在该时段发生变动）和「未应验」。若规则给出了极性，「应验」支带上该极性。

**一套一级世界**是全部分岔点「应验 / 未应验」的所有组合，大小为 2^m（m 为分岔点数）。它是有限的。以八字为例，设计文档估计一生约 40–45 个分岔点，即约 2^40 套世界；紫微约 40–55 个。

### 2.2 为什么一级世界不需要物化

一级世界的作用只有两个：被权重提取读取（第 4 段），以及在界面上展示「这个引擎眼中的人生」。权重提取只需要分岔点列表本身，不需要把 2^m 个组合列出来，所以一级世界是惰性的：契约中交付的是分岔点和倾向（`PrimaryWorld`，见 02 文档），任何一个具体组合都可以由「分岔点 ID → 应验与否」的位串确定地生成。

### 2.3 时间单位：保留原生结构，附加绝对时间

一级世界**保留各体系自己的时间结构**，不在这一步对齐到统一时间轴。理由：一级世界要回答「这个引擎怎么看」，强行对齐会丢失「大运十年」「大限十年」「Dasha 不等长」这类体系内含义。同时每个时段都带绝对日期边界，所以下游需要对齐时（第 4 段）可以直接比较，不需要额外换算。

「重大转折 `turning`」领域的关键节点（如八字交运、紫微大限换宫）在一级世界里是分岔点，但在第一版里**不生成重大选择**，只作为时间结构标记展示【自定】。理由：「转折」没有具体指向，把它映射成具体选择类型（迁居？换工作？）只能靠猜。

### 2.4 独立性保证

`worlds` 模块的函数签名是 `buildPrimaryWorld(delivery: EngineDelivery, person: PersonRef): PrimaryWorld`，只接收单个引擎的交付物。它在类型上拿不到其他引擎的结果，所以引擎之间在这一步不可能互相影响。时代背景（过去的固定事实）由出生地和年代决定，与引擎无关，同时进入每个引擎的一级世界，不破坏独立性。

### 2.5 计算量与缓存

一级世界按「人 × 引擎」生成。设人物数为 n、引擎数为 E：

- 引擎运行次数 n × E。每次运行是纯计算，毫秒级（以现有 `src/core` 的同类计算估计，未实测），8 人 × 13 引擎约 100 次，可忽略。
- 一级世界本身只是对交付物的整理，开销同样可忽略。

**缓存键**：`(personInputDigest, engineId, engineVersion, astroTimeVersion, ruleRegistryVersion)`。增删一个人物时，只需为新人物运行引擎；其他人物的引擎结果和一级世界全部复用。真正需要重算的是第 4 段之后（跨人物匹配、二级世界、坍缩），见 §4.7。

## 3. 权重提取

### 3.1 什么算「重大选择」

候选选择由两步产生，每一步都是确定的：

1. **映射**：每个分岔点按 `ChoiceTypeMap`（领域 × 当事人 → 选择类型）映射成 0 到多个候选选择。第一版映射表【自定】：

| 分岔点的领域 / 当事人 | 选择类型 |
|---|---|
| `relationship` / self 或 spouse | `partnership`（结成或解除伴侣关系，按状态实例化） |
| `migration` / self | `residence`（迁居） |
| `career` / self | `career`（职业变动） |
| `study` / self | `education`（学业路径） |
| `family` / child | `children`（生育或子女相关决定） |
| `family` / father、mother | `family_care`（照护或与父母同住的安排） |
| `wealth` / self | `major_finance`（重大财务决定，如购房、创业投入） |
| `turning` / 任意 | 不生成选择（§2.3） |
| `health` / 任意 | 不生成选择：健康不是「选择」，只作为 `healthAttention` 状态的倾向 |

2. **判定**：候选选择的重要性由三个可判定的量相乘：

```
importance(k) = irrev(type) × scope(type) × intens(k)
  irrev(type)  ∈ {0.4, 0.7, 1.0}       不可逆程度，查选择目录【自定】
  scope(type)  = min(1, 领域数(type) / 3)  影响的生活领域数，查选择目录【自定】
  intens(k)    = intensity / 3；规则不分等级（intensity = null）时取 1/3 并打标 intensity_unknown【自定】
```

第一版选择目录（节选）【自定】：

| 选择类型 | irrev | 影响领域 | scope | 对齐容差 τ |
|---|---|---|---|---|
| `partnership` | 1.0 | 情感、家庭、财富 | 1 | 1 年 |
| `children` | 1.0 | 家庭、情感、财富 | 1 | 1 年 |
| `residence` | 0.7 | 迁移、事业、家庭 | 1 | 1 年 |
| `career` | 0.7 | 事业、财富 | 2/3 | 1 年 |
| `family_care` | 0.7 | 家庭、事业 | 2/3 | 1 年 |
| `education` | 0.7 | 学业、事业 | 2/3 | 1 年 |
| `major_finance` | 0.7 | 财富、家庭 | 2/3 | 1 年 |

「重大」的判定：候选选择合并后（§3.3），**按权重排序取前 K 个**进入二级世界，K 是物化边界之一，写入输出；另设一个下限 `W_min = 0.01`，低于它的候选永远不进入。我没有用固定阈值，因为权重没有校准，绝对数值没有意义，只有相对顺序有意义。未进入前 K 的候选**不丢弃**，保留在「候选池」里，现实情境中的事实可以把它们「激活」（见 05 文档 §2.2）。

### 3.2 权重从哪里来

```
w(k) = importance(k) × reliability(k)
reliability(k) = statusFactor(engine) × verifFactor(rule)
  statusFactor: complete 1.0 / partial 0.6 / needs_source_validation 0.3 / experimental 0（不进入）【自定】
  verifFactor:  verified 1.0 / cited_unverified 0.7 / unverified 0.4 / project_assumption 0.4【自定】
```

一个分岔点涉及多条规则时（例如一条规则的宫位部分有出处、应期解读没有出处），取**最弱一环**的 `verifFactor`。

这回答了「引擎状态如何传导到下游」：引擎状态和规则可靠性在这里变成权重的乘子，并在坍缩中再次决定该引擎振幅的权重 ρ（见 05 文档 §3）。`experimental` 引擎不进入世界生成，只展示。

**诚实说明**：以上所有系数都是项目自定的主张，没有校准数据。它们的作用是让「可靠的规则」比「不可靠的规则」更有分量，具体数值没有经验依据。上线后若积累了用户反馈（`prediction_actuals` 的新版），可以用来校准，但在样本量达标之前不改变这些数值（见 11 文档）。

### 3.3 对齐与合并（同一个人）

**同一件事的判定**：两个候选 `k1、k2` 属于同一选择，当且仅当：① 选择类型相同；② 人物相同（或同属一个联合事件，见 §3.4）；③ 时间窗口在容差 τ 内相交，即 `start1 ≤ end2 + τ` 且 `start2 ≤ end1 + τ`。

**聚类算法**：把候选按 `(type, person, start, engineId, ruleId, periodId)` 排序，在「满足上述条件」的图上取连通分量。连通分量与遍历顺序无关，所以结果对引擎顺序不敏感（这是一条必测性质）。为防止链式连接把一串候选连成一个跨度过长的簇，规定簇的总跨度不超过 3τ；超过时在最大的时间间隙处切开，并列时切较早的间隙。

**合并权重**：

- 同一引擎内的多个候选（例如八字同一年既有冲日支又有天克地冲）：取最大值。同一引擎重复命中不算独立印证。
- 不同引擎：用 noisy-OR `1 − Π(1 − w_i)`【数学：独立证据的并】，但**同一「体系族」的引擎之间打折扣**【自定】：

```
family(e): chinese_calendar = {bazi, ziwei, tieban, qimen, liuren, taiyi, liuyao, meihua}
           astronomical      = {western, vedic}
           name_number       = {numerology, kabbalah}
           mesoamerican      = {mayan}
同族合并：W = max(w) + κ × (noisyOR(w) − max(w))，κ = 0.5
异族合并：W = noisyOR(各族合并值)
```

理由：八字和紫微都由同一组干支、农历数据推出，它们「一致」在相当程度上是同源，不是独立印证。如果按独立证据合并，会高估印证强度。这一点也影响建设顺序：第一个加入的非中国体系引擎（建议是西方占星）才会带来真正独立的印证（见 09 文档）。

**合并后的时间窗口**：取各候选窗口的交集；交集为空时取并集，并打标 `window_disagreement`，输出各引擎各自的窗口。

### 3.4 多人之间「分别提取、再取相同」

对每个完整人物分别做 §3.1–3.3 的提取，得到各自的候选清单。然后找出不同人物之间指向同一件事的候选。

**「同一件事」的判定规则**（`JointEventRules`，【自定】，第一版）：

| 联合事件 | 人物关系条件 | 两侧候选类型 | 时间条件 |
|---|---|---|---|
| 婚恋结成或解除 | p、q 互为（准）伴侣，或用户声明的关系 | p 的 `partnership` ↔ q 的 `partnership` | 窗口在 τ 内相交 |
| 共同迁居 | p、q 为伴侣或同住家人 | `residence` ↔ `residence` | 同上 |
| 子女出生 | p、q 为伴侣 | `children` ↔ `children` | 同上 |
| 父母变故 / 照护 | p 为 q 的子女 | p 的 `family_care`（当事人为 father/mother 中的 q） ↔ q 的任意本人类候选 | 同上 |

**权重提升**：联合事件的权重 = 各方合并权重的 noisy-OR（不同人物的出生数据是独立输入，不打族折扣）。

**一方有、另一方没有**：保留为该人物的单方候选，标 `unilateral`，并记录「对方在该窗口内无对应关键节点」。它照常进入排序，只是没有获得提升。

**双方矛盾**：两侧候选匹配上，但极性相反（一方 favorable，一方 unfavorable）。处理方式是合并为一个联合事件，**保留双方各自的极性**，打标 `polarity_conflict`。这种矛盾不在这一步消解，而是进入二级世界：双方作为两个参与者，各自按自己的收益行动（§4.3），矛盾自然体现为两人策略的不一致。

**同一个人的不同引擎之间**也是同一套「分别提取、再取相同」：§3.3 就是它的单人版本。

**输出**：`MajorChoice[]`，每项带类型、窗口、参与人物、各来源候选（引擎、规则、分岔点、权重）、合并权重、标签（`unilateral`、`polarity_conflict`、`window_disagreement`、`intensity_unknown`）。这是二级世界的唯一输入。

### 3.5 对旧事件抽取的评估

`src/utils/eventSeedExtractors.ts` 的逐项评估见 `00-现状评估.md` §4.1。结论：年龄和概率常数全部弃用；「以引擎自有时间结构为触发点」和「回溯字段」的思路保留。新设计中，旧抽取器的角色由「引擎的 `key_node` 规则 + `ChoiceTypeMap`」取代，每一步都有 `ruleId` 或标为【自定】的映射条目。

## 4. 二级世界

### 4.1 博弈的形式化

二级世界是一个**有限期、带自然参与者的多阶段博弈，阶段间信息可观测，阶段内同时行动**（multi-stage game with observed actions）【数学】。

- **阶段**：重大选择按窗口起点排序，并列时按选择目录中的类型顺序、再按选择 ID 决胜。阶段 k 对应选择 `c_k`。
- **参与者**：阶段 k 的参与者集合 `N_k(s)` 由当时的世界状态 s 和选择目录决定，可能包括：本人、相关他人（完整人物或推导人物）、「机会」参与者、「环境」参与者。
  - **机会参与者**【自定】：决定这个选择机会是否真的出现。出现概率 `P(arise) = b₀ + (1 − b₀) × w_e(k)`，其中 `w_e(k)` 是引擎 e 对该选择的支持（同一引擎下各人物支持的 noisy-OR），b₀ = 0.5 为无信息基准。它把「引擎说这里有个关口」翻译成「关口出现的可能性更高」。
  - **环境参与者**【自定】：对需要环境的选择类型（迁居、职业、重大财务），策略为「扩张 / 平稳 / 收缩」。过去的阶段若有对应的时代记录，就按记录固定；没有记录的过去阶段和所有未来阶段，均匀先验。
- **策略**：每个人物参与者的策略集合由选择目录给出，第一版都是二元的，例如 `partnership` 结成时为 {承诺, 拒绝}，解除时为 {留下, 离开}；`residence` 中本人为 {迁, 留}，配偶为 {同意, 反对}，父亲为 {支持, 反对}。
- **结果函数**：策略组合加上机会和环境的取值，映射到一个**结果**。例如结婚当且仅当「机会出现 ∧ 双方都承诺」；解除伴侣关系当且仅当「机会出现 ∧ 至少一方离开」；迁居结果为「迁且顺利 / 迁但受挫（环境收缩）/ 未迁」。
- **状态转移**：每个结果按选择目录改写世界状态。

**是否完全信息**：阶段之间是完全信息（每个阶段开始时，前面所有阶段的结果都已知）；阶段之内是不完全信息（同时行动，并且不知道环境将取哪个策略）。

### 4.2 收益函数

参与者 i 在引擎 e 的世界里，对阶段 k 的「改变」策略的收益：

```
s_{i,e}(k) = 该人物在引擎 e 下、阶段 k 的窗口内、该选择类型所涉领域中，
             当事人为本人的所有信号极性的均值
             极性取值：favorable +1，unfavorable −1，mixed 0，neutral 0；无信号时为 0
             intensity 有值时作为权重参与加权平均
```

- **完整人物**用自己的引擎信号；**推导人物**（如没有出生信息的父亲）用本人命盘中对应 `relationSlot` 的信号。
- **每个引擎单独构成一个博弈**：在八字的博弈里，所有参与者的收益都来自八字；在紫微的博弈里，都来自紫微。这保证了「各引擎各自成世界」一直延续到第 5 段，引擎之间的结合只发生在坍缩时的振幅叠加（05 文档）。
- **维持现状的惯性**【自定，依据行为决策研究中的现状偏差（Samuelson & Zeckhauser, 1988, *Journal of Risk and Uncertainty*）】：每个参与者的「维持现状」策略有额外收益 ι = 0.5。没有它，在引擎信号全为中性时，「至少一方离开即解除」这类结果规则会凭空制造很高的变动概率。
- **状态修正**：选择目录中的修正项，例如迁居时与父亲同城，则本人「迁」的收益减去 0.5 × P(父亲反对)【自定】。

阶段 k 中，参与者 i 的「改变」相对「不变」的期望收益差 Δu_i 由其他参与者的策略分布决定。例如：

```
结婚（双方都承诺才成）：Δu_A = P_B(承诺) × (s_A − ι)
解除（任一方离开即成）：Δu_A = P_B(留下) × (−s_A − ι)
迁居（需配偶同意）：   Δu_A = P_B(同意) × (s_A − ι − 0.5 × P_F(反对)·[与父同城])
```

### 4.3 均衡概念的角色：用于给世界加权，不用于剪枝

我建议用 **logit 量化响应均衡（QRE）**【数学：McKelvey & Palfrey, 1995, *Games and Economic Behavior*】：

```
P_i(改变) = σ(λ · Δu_i)，σ(x) = 1 / (1 + e^(−x))，λ = 2【自定】
```

所有参与者的 P_i 同时满足上式（不动点）。求解用固定次数的迭代（500 次，从 0.5 出发），迭代次数写入算法版本。

为什么不用纳什均衡或子博弈完美均衡做「生成」或「剪枝」：

- 纳什均衡只保留均衡策略，非均衡的世界概率为零，与「无穷多元世界都存在、只是振幅不同」的设想矛盾。QRE 让每个策略组合都有正概率，同时让更符合收益的策略更可能。λ → ∞ 时 QRE 收敛到纳什均衡，λ = 0 时退化为均匀随机，所以它把「均衡」作为一个连续的加权原则，而不是一刀切的筛选。
- 子博弈完美均衡需要对整棵树做逆向归纳，每个阶段的收益要包含所有后续阶段的继续价值，计算量随树深指数增长。第一版的 QRE 是**阶段性的**：参与者只看当前阶段的收益，不做前瞻【自定，简化】。这是一个明确的建模限制：人在做决定时其实会考虑后果。第二版可以加入有限步前瞻（例如看一个阶段）。

### 4.4 穷举

在每个阶段，对全部参与者的全部策略组合、机会参与者的两种取值、环境参与者的三种取值做完全枚举，计算每个组合的概率（各参与者 QRE 概率之积 × 机会概率 × 环境先验），再按结果函数汇总到结果上：

```
P_e,k(o | s) = Σ_{组合 σ → 结果 o} Π_i P_i(σ_i) × P(arise 取值) × P(env 取值)
```

**分支因子估计**：第一版每阶段人物参与者 1–3 个（二元策略），加上机会（2）和环境（3），策略组合数最多 2³ × 2 × 3 = 48；结果数 2–4 个。所以世界树的分支因子（按结果计）是 2–4。

**深度估计**：K 个选择，深度为 K。推荐默认 K = 12。完全展开的结果序列数约 3¹² ≈ 53 万，单人单机可以完全枚举（用于小规模的暴力校验）；K = 20 时约 35 亿，不能枚举，但第 6 段的求解（05 文档 §4）是动态规划，复杂度只与状态数成线性关系。

**前一个选择如何改变后续选择**：通过状态。后续阶段的①是否存在（前置条件）、②参与者集合、③策略的收益修正，全部是状态的函数。例如：第 3 阶段若「解除伴侣关系」，第 4 阶段的迁居中配偶就不再是参与者。

### 4.5 「无穷」的形式化与物化边界

你的设想（惰性结构 + 确定地址 + 由地址纯函数生成节点 + 显式物化边界）在数学上是成立的，我采纳并补充两点形式化细节。

**地址**：

```
WorldAddress = v1 / <rootDigest> / <step₁> / <step₂> / … / <step_d>
step_j       = <choiceId>=<outcomeId>[@<timeSlot>]
timeSlot     = 'Y2016' | 'Y2016M03' | …   （时间精度层级 r：年、月、日…）
```

- `rootDigest` 是所有输入（全部人物的规范化输入、选择清单、目录版本）的哈希。
- 给定地址，`nodeAt(address)` 从根状态开始依次应用各步的结果，纯函数地重建该节点的状态与概率。地址与节点一一对应：不同地址必然导致不同的结果序列，相同结果序列只有一种规范写法（这是必测性质）。
- 跳过的阶段（前置条件不满足）不出现在地址里，`nodeAt` 在重建时会确定地判断哪些阶段被跳过。

**为什么空间是无穷的**：有两个方向可以无限细化：① 时间精度 r（年 → 月 → 日 → …）：一个结果在窗口内的发生时刻可以不断细分；② 候选选择：候选池中低于前 K 的候选，可以按权重依次加入。两者都使地址集合成为可数无穷的。

**概率如何在细化中保持一致**：细化时，一个结果被拆成若干子时段，子时段的概率之和必须等于父结果的概率（Kolmogorov 一致性【数学】）。第一版的时段拆分规则：若引擎有更细的时间单位信号（如流年下的流月），按这些信号的极性 softmax 分配；没有就均匀分配，并打标 `uniform_refinement`【自定】。这样，任意有限精度下的概率分布都是同一个无穷空间上的测度在该精度上的投影。

**物化边界**写入每个输出：

```ts
interface MaterializationBounds {
  maxChoices: number;       // K，默认 12
  timeResolution: 'year' | 'month';  // r，第一版默认 'year'
  horizonYear: number;      // H，推演边界
  candidatePoolSize: number; // 候选池总数，用于说明「还有多少没物化」
}
```

### 4.6 已知局限（同时写入 11 文档）

1. **信号为中性时，结果由【自定】参数决定。** 第一版八字不给极性（八字设计文档：不做用神，一律 `mixed`/`neutral`），所以八字世界中的博弈收益几乎全为 0，策略分布完全由 b₀、ι、λ 和结果规则决定。这意味着在第一版里，八字主要贡献「哪里有关口、关口的分量」，不贡献「往哪个方向走」。
2. **没有基准发生率。** 「一个人一生中某年结婚的可能性」本应来自时代与地域的统计（`era-data` 的人口统计指标），第一版用 b₀ = 0.5 代替。
3. **阶段性 QRE 没有前瞻。**
4. **K 的截断会改变结果。** 未物化的选择不影响路径，稳定性检验见 05 文档 §5。

### 5.5 二级世界（第 5 段）：逐阶段计算

**N1 · 2016 结婚**（结果：结婚 / 未婚）。

- 八字的世界：A、B 在 2016 年的 relationship 信号均为 `mixed` → s_A = s_B = 0。机会：P(arise) = 0.5 + 0.5 × 0.1536 = 0.5768。QRE 不动点：Δu_A = P_B × (0 − 0.5)，Δu_B 同理，解得 P_A = P_B = 0.4011。P_八字(结婚) = 0.5768 × 0.4011² = **0.0928**。
- 紫微的世界：s_A = −1（廉贞化忌入夫妻宫），s_B = +1（天同化禄入夫妻宫）。紫微没有该节点的 key_node 候选 → P(arise) = 0.5。不动点：P_A = σ(2 × P_B × (−1.5))，P_B = σ(2 × P_A × 0.5)，解得 P_A = 0.1648，P_B = 0.5411。P_紫微(结婚) = 0.5 × 0.1648 × 0.5411 = **0.0446**。
- 这里可以看到两个人的引擎都在起作用：B 的紫微倾向于这段婚姻，A 的紫微不倾向，结果是 A 承诺的概率低。

**N2 · 2016 迁居**（结果：迁且顺利 / 迁但受挫 / 未迁）。以 N1 = 结婚为前提（现实情境会确认这一点）：参与者 A、B、F、机会、环境。初始状态中 A 与 F 同在北京：没有现实情境时，推导人物的居住地默认为本人出生地【自定】，现实情境可以覆盖它。

- 八字：s_A = s_B = 0，F 的信号（A 命盘父亲位）也为 0 → P_F(支持) = 0.5，A 的修正项 −0.5 × 0.5 = −0.25。P(arise) = 0.5 + 0.5 × 0.1089 = 0.5544。不动点：P_A = 0.3497，P_B = 0.4134。P(迁) = 0.5544 × 0.3497 × 0.4134 = 0.0801，按环境先验拆为顺利 2/3、受挫 1/3：**(0.0534, 0.0267, 0.9198)**。
- 紫微：A、B 在迁居相关领域无本人信号 → 0；但 F 的信号为 favorable（2016 天同化禄入 A 的父母宫）→ P_F(支持) = σ(2) = 0.8808，A 的修正项只有 −0.5 × 0.1192 = −0.0596。P(arise) = 0.5，不动点 P_A = 0.3888，P_B = 0.4040 → **(0.0524, 0.0262, 0.9215)**。
- 这里可以看到推导人物 F 起了作用：紫微眼中父亲当年状态好、更可能支持，所以 A 迁出的阻力更小。

**N3 · 2028 解除伴侣关系**（结果：解除 / 继续）。两个引擎在 2028 年的 relationship 信号对 A、B 都是 0。

- 八字：P(arise) = 0.5768；不动点：每人「离开」概率 0.3410；P(解除) = 0.5768 × (1 − 0.659²) = **0.3263**。
- 紫微：P(arise) = 0.5；P(解除) = **0.2828**。
- 这个数值偏高，完全来自【自定】参数（b₀、ι、λ 和「任一方离开即解除」的结果规则），没有任何引擎依据。这正是 §4.6 第 1、2 条局限的实例：没有方向信号、没有基准发生率时，模型只是在表达参数。它在界面上必须如实显示为「无引擎依据的节点」（07 文档）。

**N4 · 2028 迁居**依赖 N3 的结果（配偶是否仍是参与者）和 N2 的结果（是否与父亲同城），所以没有单一数值，在坍缩时按状态计算（05 文档 §6）。紫微在 2028 年对 A 有 career favorable 倾向（贪狼化禄入官禄）→ s_A = +1，这使紫微世界中 A 更倾向迁居。

到此，第 5 段的产物是：4 个阶段、每个阶段在每个引擎世界里关于每个可达状态的结果分布。完整的结果序列共 2 × 3 × 2 × 3 = 36 条（一部分在状态约束下不可达），它们就是这个小例子在物化边界内的二级世界。坍缩接着在 05 文档 §6 进行。
