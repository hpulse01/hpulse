## 3. 我认为最可能出错的地方

### 3.1 引擎给不出方向，第一版的路径主要由参数和现实决定

八字第一版不做用神，信号一律 `mixed` / `neutral`；紫微的方向性规则全部是 `unverified`，且引擎状态可能只有 `needs_source_validation`。在例子中，四个节点里只有两个节点有任何引擎方向，而且都来自紫微的未核实规则。结果是：**过去段几乎完全由现实情境决定，未来段主要由【自定】参数（b₀、ι、λ、结果规则）决定。** 这是诚实的，但它意味着第一版的「唯一路径」与其说是命理推演，不如说是「命理指出关口 + 参数补全方向」。

**缓解**：界面上逐节点标出「本节点没有引擎方向」；尽早加入西方占星（能给方向且天文部分可严格验证）；八字的喜忌模块作为 `experimental` 评估。

### 3.2 【自定】参数的数值没有依据，而且会主导结果

例子中 N3（2028 年解除伴侣关系）的概率 0.31 完全来自参数。稳定性检验能告诉你「路径对参数扰动是否敏感」，但不能告诉你「参数是否正确」。在积累足够的用户反馈之前，没有任何办法校准它们。

**缓解**：参数集版本化；界面显示参数主导的节点；`path_feedback` 从第一天收集；第 7 阶段设计校准，样本量达标前不回写。

### 3.3 黄金用例的取得会卡住进度

几乎所有规则都缺典籍的具体版本和卷章；八字、紫微的外部排盘数据需要你指定软件并取得；铁板缺可授权底本。没有这些，引擎永远停在 `partial` 或 `needs_source_validation`，并且通过 statusFactor 直接压低引擎在世界生成中的分量。

**缓解**：第 1 阶段就开始取数据；06 文档 §7 的清单按优先级排好；紫微黄金用例不阻塞第 3 阶段。

### 3.4 「取最大概率路径」与「抽样」之间的选择会被低估

见 D4。如果选择 A 而没有意识到它偏向平淡路径，第一版上线后用户看到的未来段会几乎全是「维持现状」，这会被理解为产品没有用。

### 3.5 同源引擎的「印证」被高估

八字、紫微、铁板、奇门等都建立在同一套干支和农历数据之上。族折扣 κ = 0.5 是一个粗糙的修正，真实的相关程度不知道。如果相关性比假设的更强，跨引擎印证带来的权重提升就仍然偏高。

### 3.6 现实情境的录入质量

事实的年份常常记不准（「大概是 2016 还是 2017 年」）。κ(1) = 0.5 的容差能吸收 1 年的误差，但如果用户记错 2 年，就会被判为矛盾并触发「现实强制节点」，路径中出现一个引擎没有指向的事件。

**缓解**：允许事实填写年份区间；冲突报告中提示「如果你不确定年份，可以填一个区间」。

### 3.7 敏感数据

第三方的出生信息和家庭情况是这个产品最敏感的数据。任何一个日志、埋点或 AI 调用的疏漏都会造成泄露。旧代码中已经出现了新增 MCP 出口返回出生信息的情况（00 文档 §2），说明这类风险会被自动化工具在不经意间引入。

**缓解**：08 文档 §4 的规则写进 `CLAUDE.md`；静态检查；第 5 阶段用带特征值的测试数据检查日志。

## 4. 我对你的设想不同意或修改过的地方（汇总）

1. 分支定义在结果上，不在策略组合上（04 §0）。
2. 纳什 / 子博弈完美均衡不用于生成或剪枝，改用 QRE 加权（04 §4.3）。
3. 相位只取 0 和 π，并引入「部分相干」；干涉只发生在节点内，历史之间正交（05 §3）。
4. 「重大」用前 K 排序而非固定阈值（04 §3.1）。
5. 建设顺序前加第 0 阶段；第一个补充引擎选西方占星（09 §0）。
6. 推演边界不用固定年龄，用 `asOf` + N 年（D6）。
7. 新增 `detmath`、`rule-registry`、`era-data` 三个模块；`reality` 与 `multiverse` 同层（01 §1）。
