# 07 · 界面与产品流程

## 0. 结论先行

- 普通用户看到的只有一条主线：**输入 → 补充现实 → 唯一路径**。多元世界和回溯链默认收起，按需展开，用「三层深度」控制信息量。
- 「唯一路径」页分「已发生」和「推演」两段，每个节点同时显示所选结果、它的概率，以及最可能的另一个结果。凡是由【自定】参数主导、没有引擎方向的节点，都直接标出来。
- 超管的 23 个 Tab 全部取消，研究和审计功能并入同一套页面的「深度 3」，按角色开放。
- 中英双语从第一天起所有文案走词条表；移动端优先设计。

## 1. 页面与导航

| 页面 | 路径 | 内容 | 谁能看 |
|---|---|---|---|
| 首页与免责声明 | `/` | 产品是什么、不是什么（非科学预测、非医疗法律金融建议、不输出寿命），勾选同意后进入。保留现有的强制免责流程 | 所有人 |
| 本人信息 | `/me/birth` | 出生日期、时间（含「不确定」选项和精度）、出生地（地图检索，自动给出 IANA 时区，夏令时重叠时让用户选择）、性别（可不填，并说明会影响哪些引擎） | 登录用户 |

## 2. 现实情境如何采集而不让人厌烦

1. **先给结果，再要现实。** 只填本人出生信息时就跑完第 2–5 段，展示「你的命盘提取出的人生关口」（带年份和类型的时间轴）。用户看到具体关口，才知道补充现实有什么用。
2. **按关口提问，不按表格提问。** 「引擎认为 2016 年前后你在婚恋上有一个关口。这一年前后，你的婚恋状况有变化吗？」三个按钮：「有，是…」「没有」「不想说」。每回答一个，路径的「已确定」计数就加一，用户能看到回答的作用。
3. **每页 3–5 题**，可以随时离开，下次从断点继续。
4. **完整性声明放在每个区块末尾**：「这个方面我已经全部列出」，旁边一句解释：「勾选后，没有列出的就会被当作没有发生」。
5. **自由文本入口**（若 D1 允许 AI 抽取）：「或者，用一段话讲讲你的经历」，AI 生成草稿条目，逐条确认。
6. **不问的不收集**：每个问题旁有「这会影响什么」的小字，说不出影响的问题不出现。

## 3. 唯一路径如何呈现

### 3.1 版面（移动端，从上到下）

1. **顶部摘要**：一句话：「根据你的命盘（八字、紫微）和你提供的 7 条现实信息，这是你的唯一路径。推演到 2032 年。」以及两个数字：「已确定的过去关口 3/4」「路径概率 41.6%」。旁边的「这是什么意思」展开解释概率的含义（这是模型内部的概率，没有经过现实校准）。
2. **时间轴**，以 `asOf` 为界分两段，视觉上明显区分：
   - **已发生**（实线，灰底）：每个节点标「你提供的事实」「部分由事实确定」「推断」三种徽章之一。
   - **推演**（虚线，主题色）：每个节点卡片显示：年份、选择类型、所选结果、所选结果的概率；若最可能的结果不是所选结果，显示「最可能的是…（xx%）」；若所选结果概率低于 10%，显示「低概率关口」；若节点没有任何引擎方向，显示「本节点主要由模型参数决定，引擎未给出方向」。
3. **终点**：「推演边界 · 2032 年。这是本次分析覆盖的范围，不是寿命估计。」
4. **冲突与提示**卡片（若有）：「紫微对你 2016 年的婚恋给出了不利倾向，而你在这一年结婚。」「八字在 2019 年指向子女方面的关口，而你说明没有子女。」冲突是有价值的信号，用中性语气呈现，不道歉、不掩饰。
5. **稳定性**一句话：「这条路径在参数变化 ±20% 时保持不变。」

### 3.2 节点的三层深度

| 深度 | 显示什么 | 默认 |
|---|---|---|
| 1 · 结论 | 年份、类型、所选结果、概率、徽章 | 展开 |
| 2 · 依据 | 哪些人物、哪些引擎、哪条规则（规则名称 + 可靠性标签：典籍有出处 / 有出处未核对 / 未核实 / 项目假设）；参与者及其倾向（「你：倾向留下 60%；配偶：倾向反对 64%」）；起作用的现实条目；被排除的邻近结果及原因 | 点击展开 |
| 3 · 审计 | 完整 `TraceChain`：世界地址、每个引擎的博弈（策略组合表）、叠加计算（经典项与干涉项）、规则登记原文、引擎盘面路径 | 「查看计算过程」，所有用户可见，但折叠在最深层 |

可靠性标签用颜色加文字，不只用颜色（色盲可读）。

### 3.3 新旧路径的差异

现实情境更新后，路径页顶部出现「与上一版相比」条：列出变化的节点，每项一句话说明原因，例如「2016 年迁居：由『迁居』变为『未迁居』，因为你修改了 2017 年的迁居记录」「2028 年迁居：结果不变，概率由 90.6% 变为 91.3%，因为你与父亲同城，父亲成为这个选择的参与者」。点开进入 `/path/history` 的完整对比视图。

## 4. 多元世界如何浏览

- **邻近世界列表**：按后验概率排序的前 10 个被排除的世界，每个显示「从哪个节点开始不同」「不同在哪里」「为什么没选它」。点击后用同样的时间轴版面展示该世界，顶部固定提示「这不是你的唯一路径，是一个被排除的世界」。
- **分叉视图**：在唯一路径的任一节点上点「看其他可能」，展示该节点的全部结果及其概率（条形图），每个结果可以继续往下看一步。
- **一级世界视图**（引擎页内）：单个引擎眼中的人生，时间轴上标出分岔点，可切换「应验 / 未应验」查看。
- 不提供「生成全部世界」的按钮：世界是可寻址的，但不需要、也不应该一次性列出。

## 5. 回溯链如何展示而不淹没普通用户

- 普通用户默认只看深度 1，节点上的一个「依据」链接进入深度 2。
- 深度 2 用自然语言模板生成（不是 AI 生成），每句都对应结构化数据，例如「这个关口来自你和配偶的八字：2016 年流年申冲你们的日支（规则：地支六冲 + 冲日支主婚动，后者未核实）」。
- 深度 3 是表格和公式，面向想核对计算的用户与研究人员。
- **AI 解读**作为可选的第四种视图「用白话解释这个节点」：调用 Edge Function，输入为该节点的结构化数据，输出标明「AI 生成，仅作解释，不参与路径计算」，并附 `deterministicInputsHash`。AI 文本永远不写回任何计算结果。

## 6. 中英双语

- 所有界面文案、规则名称的展示名、模板句都在词条表 `apps/web/src/i18n/{zh,en}.json` 中；规则登记表中每条规则有 `title.zh` 与 `title.en`。
- 命理术语的英文用「拼音 + 意译」，例如「Liunian (annual pillar)」，词汇表放在 `docs/glossary.md`。
- 日期显示按用户语言格式化，但只在界面层；算法层不接触任何语言环境 API。
- 词条表的完整性由 CI 检查：两种语言的键集合必须相同。

## 7. 移动端

- 设计从 360 px 宽开始，时间轴纵向排列；节点卡片在移动端点击展开为底部抽屉。
- 计算在 Web Worker 中进行，界面显示真实的阶段进度（「正在运行引擎 3/26」「正在生成二级世界」），没有人为延迟。
- Capacitor 外壳：第一版是否发布原生 App 见 10 文档 D13；无论是否发布，Web 版本都按移动端优先实现，外壳只是打包。

## 8. 从旧界面保留的东西

- 免责声明的强制同意流程、`ErrorBoundary`、shadcn/ui 组件与 `tailwind.config.ts` 的设计 token、`docs/UI_SYSTEM.md` 中「克制、审计优先」的原则。
- 不保留：23 Tab 结构、`components/quantum/*` 的可视化（雷达、波形、相干、纠缠图）、13 个独立引擎 Tab。
