# H-Pulse 宪法 v3（草稿）

> 取代 `docs/hpulse/01-constitution.md`（constitution.v2）。本文件是项目一切代码、算法、数据与文档的最高约束；与本文件冲突的设计在评审中直接拒绝。
> 状态：草稿，经项目负责人确认后生效。

## 第一条 · 唯一目的

H-Pulse 的唯一目的：**根据一个人的出生信息，推演出他唯一的人生路径。**

唯一路径是产品的最终输出。它就是本产品所称的「命运」。

## 第二条 · 六段式流程（不可更改）

1. **输入**：出生年月日时，以及各引擎排盘所必需的出生地、时区、性别。
2. **命理引擎**：同一份输入分别进入多个相互独立的命理引擎，每个引擎按自己体系的规则生成结果。
3. **一级世界**：每个引擎根据自己的结果各自生成一套世界，引擎之间互不干扰。
4. **权重提取**：从每个世界里按权重提取「重大选择」，即人生中真正分岔的决策点。
5. **二级世界**：以提取出的全部重大选择为素材，用博弈论的穷举法展开，生成无穷多元世界。
6. **现实坍缩**：结合用户的现实情境做多元分析，对无穷世界做量子坍缩，得到唯一路径。

第 3 到 6 段生成的世界是真实的世界：有用户的家人和重要他人，有家庭、成长环境、地域、时代和社会；这些人和环境有自己的状态，会变化、会行动、会与用户相互影响。

情景树、多元世界与坍缩是主流程，不是研究功能。「量子坍缩」是产品的核心概念和正式名称。

## 第三条 · 确定性

1. 同样的出生信息、同样的现实情境、同一个算法版本，必须得到同一条唯一路径，字节级一致。
2. 现实情境改变时，路径可以随之改变，但必须能指出是哪一项现实信息导致了哪一处改变。
3. 算法路径中不得出现 `Math.random`、`Date.now()`、无参 `new Date()`、依赖系统时区或语言环境的 API，以及未经确定性封装的超越函数。
4. 坍缩若需要随机性，种子必须由出生信息确定性地派生，并写入输出。
5. 所有集合的遍历和排序都有确定的次序与并列决胜规则。

## 第四条 · 不编造规则和来源

1. 每条实现的规则都有稳定的 `ruleId`，登记来源（典籍名 + 版本 / 卷章，或权威技术参考）和所属流派。
2. 不确定出处的规则照实标 `unverified`，不补一个看起来合理的引用。
3. 没有规则依据的数值宁可不输出并说明原因，不用哈希、取模或固定常数填补。

## 第五条 · 黄金用例必须独立

验证引擎的期望值必须来自代码之外：典籍成例、天文历表、公认的排盘结果。被测代码自己生成的快照只算回归测试，不算验证，两者分目录、分计数。拿不到外部数据时列成清单，不自己造。

## 第六条 · 全程可追溯

唯一路径上的每个节点都能向上回溯：二级世界的分支 → 博弈局面与策略组合 → 重大选择及其来源（哪个人物、哪个引擎、哪个一级世界、多大权重）→ 引擎规则。坍缩为什么选这条而不是别的，必须能用数据解释：概率、起作用的现实情境条目、被排除的邻近世界及其数值。不存在只有自然语言结论的输出。

## 第七条 · 模型的诚实

1. 第 3 到 6 段是本项目自己提出的模型。设计与代码中的每一处建模假设都明确标注为三类之一：来自命理典籍的规则、来自博弈论或量子力学的标准数学、项目自定义的假设。
2. 量子坍缩是借用量子力学数学形式（态叠加、振幅、干涉、测量坍缩）的经典计算，运行在普通计算机上。技术文档按这个事实描述，不写成使用了量子硬件或物理量子效应。
3. 项目自定义的参数在没有校准数据之前，是项目的主张，不称为经过验证的事实。

## 第八条 · 引擎状态诚实

1. 每个引擎声明实现状态（`complete` / `partial` / `needs_source_validation` / `experimental`）和来源等级。
2. 升到 `complete` 的条件是可执行的检查：所有规则有 ID 和来源；声明范围内无缺失规则；独立黄金用例覆盖正常、边界、非法、歧义四类输入。
3. 引擎状态传导到下游：未充分验证的引擎在世界生成与坍缩中的分量相应降低，`experimental` 引擎不进入世界生成。

## 第九条 · 安全边界

1. 不输出寿命、死亡时间或同类结论；这类事件在类型层面就不存在。路径的终点是「推演边界」，不是寿命估计。
2. 出生信息、姓名和现实情境都是敏感个人数据：不进日志，不进分析埋点；现实情境只收集坍缩确实用得上的条目；用户可以查看和删除。
3. 对第三方更克制：用户可以录入他人的出生信息并对其运行引擎；这些数据只归属于录入它的用户、只用于生成该用户的世界，默认用关系称谓而不是真实姓名，不向任何其他人展示，随用户数据一并删除；录入前有明确提示。
4. AI 生成的解读文本只做解释，不参与世界生成和坍缩。
5. 用户进入分析前必须接受免责声明。

## 第十条 · 版本化

所有算法、规则、目录、参数、数据集都版本化，复合版本号写入每一次输出。任何改变输出字节的改动都必须升版本。
